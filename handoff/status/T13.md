deepagents version: 0.7.38 (langchain 1.5.0, langgraph 1.2.22). API used:
- `create_deep_agent(model, tools, *, system_prompt, middleware, subagents, memory, interrupt_on, checkpointer)`
- Sub-agents: dicts with `name`, `description`, `system_prompt`, `tools`, `model` (one model per sub-agent).
- Planning is opt-in: `middleware=[TodoListMiddleware()]` (`langchain.agents.middleware`); todos come from
  `state["todos"]` through `astream(..., stream_mode="values")`.
- general-purpose turned off with `register_harness_profile(<model spec>, HarnessProfile(general_purpose_subagent=GeneralPurposeSubagentProfile(enabled=False)))`,
  keyed on our exact model string (models passed as instances, like the fakes in tests, keep it).
- Questions: `interrupt_on={"ask_user": {"allowed_decisions": ["respond"]}}`; pending from
  `(await agent.aget_state(cfg)).interrupts`; resume with `Command(resume={interrupt.id: {"decisions": [{"type": "respond", "message": ...}]}})`.
- Threads: `InMemorySaver()` with `thread_id = run_id`.
- Memory: `memory=["/AGENTS.md"]` in the default `StateBackend`, given as input `files={"/AGENTS.md": create_file_data(text)}`.
  `memory` reaches only the main agent, so the sub-agents' prompts include the house rules too.
- Parallel firmware + enclosure: two `task` calls in one message (ToolNode runs them at the same time).
  Async sub-agents need a LangGraph server, so we don't use them.
- `P2D_MODEL`: `provider:model` or a bare name (gets `anthropic:` in front).

Done:
- `backend/agent/runner.py`: `AgentRunner(toolbox, model, run_stages, *, lib=None, models=None, question_timeout_s=120, max_questions=2)`
  with `run()`, `edit()` and `answer()`. `models` = per-sub-agent overrides (e.g. `{"parts-and-pins": "anthropic:<stronger>"}`).
- `backend/agent/tools.py`: `search_parts`, `write_spec` (code sets prompt/user/rev, saves only after
  validate passes), `write_firmware` (optionally updates `firmware.behaviors`), `set_enclosure`, `price_bom`,
  `request_change`, `ask_user`. A retry guard (1 try + 3 retries) adds `data.attempt` to the StageRunner's events.
- `backend/agent/orchestrator.py`, `AGENTS.md`, `prompts/*.md`.
- Review round 1 fixed: a failed edit() (no new rev saved) now emits plan failed and raises;
  write_firmware checks the retry limit before writing main.cpp. Regression test for each.
- Tests: one per acceptance criterion, plus tests for the question/answer/timeout path and the general-purpose removal.

Notes for B-api (consumer):
- `run()` raises `RuntimeError` when no spec passed validation, and `edit()` when no new spec (rev + 1)
  passed: treat it as a failed run. Both emit `plan` `failed` first.
- Bind the StageRunner before passing it (e.g. `functools.partial(run_stages, toolbox=..., lib=...)`).
- Edit history is in memory: after an API restart `edit()` starts a fresh thread (it still gets the current spec).
- "Rewrite main.cpp only when parts, pins or behaviours changed" is up to the orchestrator prompt; a
  stale main.cpp shows up in the engine's firmware rerun.
